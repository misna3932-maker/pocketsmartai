# PocketSmart AI

PocketSmart AI is a budget planning and recommendation web app built from the uploaded PocketSmart AI design/project document. The source describes three planners (Home Interior, Party, Jewelry), Gemini-based personalization, authentication and sessions, platform-specific shopping links, and recommendation history. The UI implementation follows the supplied screenshots with deep navy navigation, blue gradient hero bars, pale authenticated backgrounds, white rounded cards, compact form sections, and blue pill-style actions.

## Included

- Landing page with planners, testimonials, CTA, footer
- Register, login, logout
- Dashboard with three planner cards
- Home Interior planner + structured recommendations
- Party planner + budget breakdown, venue suggestions, shopping links
- Jewelry planner + optional outfit image upload + styling output
- Recommendation history + full detail pages
- `/token`, `/session-info`, `/session-data`, `/recommendations-details`, `/health`
- SQLite persistence
- Optional Gemini REST integration with graceful local fallback
- Responsive HTML/CSS/vanilla JS
- Tests, `PLAN.md`, and `TRACKING.md`

## Source note
The document contains an early Flask reference but its later milestones repeatedly specify FastAPI, Uvicorn, modular routes, and Jinja2. This build therefore uses FastAPI while preserving the route and UI concepts from the document. The source also calls for mock API calls or simulated sourcing; this implementation uses server-generated search links to named platforms rather than scraping them.

## Quick start

```bash
cd PocketSmartAI
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env
# macOS/Linux: cp .env.example .env
uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000`.

## Main routes

| Route | Purpose | Auth |
|---|---|---|
| `/` | Public landing page | No |
| `/register`, `/login`, `/logout` | Account lifecycle | No |
| `/dashboard` | Planner dashboard | Yes |
| `/planner/home`, `/planner/party`, `/planner/jewelry` | Planner forms | Yes |
| `/generate-home`, `/generate-party`, `/generate-jewelry` | Generate and save recommendation plans | Yes |
| `/history` | Saved recommendation history | Yes |
| `/recommendations/{id}` | Reopen a saved recommendation | Yes |
| `/recommendations-details?id=...` | Recommendation JSON | Yes / bearer supported |
| `/token` | Issue bearer token | Credentials |
| `/session-info`, `/session-data` | Session metadata/data | Yes / bearer supported |
| `/health`, `/startup` | Runtime readiness | No |

## Configuration

Use `.env` based on `.env.example`:

- `SECRET_KEY` signs the browser session/JWT.
- `GEMINI_API_KEY` enables AI generation.
- `GEMINI_MODEL` selects the accessible Gemini model. It defaults to the Gemini 1.5 Flash direction stated by the source document, but should be changed when the deployment uses a different accessible model.
- `GEMINI_API_URL` controls the REST endpoint.
- `MAX_UPLOAD_MB` controls outfit image size.
- `DATABASE_PATH` controls the SQLite file.

## AI fallback

The app is fully usable with no Gemini key. In that case it uses deterministic recommendations matching the same structured result format, so all planner flows and history still work. When Gemini is enabled, planner-specific JSON prompts are sent to the configured model, optional jewelry images are included, and marketplace destination URLs are generated by the server from item names.

## Data and security

SQLite stores users and recommendation history. Passwords use PBKDF2-HMAC-SHA256 with per-user salts. Sessions use an HTTP-only signed JWT-compatible cookie. The project is demo-ready; a production deployment should add HTTPS-only cookies, CSRF protection, rate limiting, email verification, password reset, and managed secret storage.
