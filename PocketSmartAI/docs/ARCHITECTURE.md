# PocketSmart AI — Architecture

## Runtime

PocketSmart AI is a single FastAPI application serving Jinja2 HTML and static assets. The design document describes both Flask and FastAPI at different stages; this build follows the later FastAPI milestones and keeps the application lightweight.

```text
Browser
  |
  | HTML forms / links / optional image upload
  v
FastAPI (`app/main.py`)
  |
  +--> Jinja2 templates (`app/templates/`)
  +--> Session/JWT auth (`app/services/auth.py`, `app/security.py`)
  +--> Planner input validation (`app/models/schemas.py`)
  +--> Recommendation service (`app/services/recommender.py`)
  |       |
  |       +--> Gemini adapter (`app/services/gemini.py`) [optional]
  |       +--> Marketplace search-link builder (`app/services/platforms.py`)
  |
  +--> Repository layer (`app/repositories.py`)
          |
          +--> SQLite (`instance/pocketsmart.db`)
          +--> Outfit uploads (`instance/uploads/`)
```

## Planner flow

Each planner follows the same sequence:

1. Authenticated user opens a planner form.
2. Browser submits the form to its `/generate-*` route.
3. Pydantic validates the numeric and list inputs.
4. Jewelry validates and stores an optional image before the AI call.
5. Gemini is called when `GEMINI_API_KEY` is configured.
6. The response is normalized into the same display structure used by the local fallback.
7. Marketplace URLs are generated by the server from recommendation queries.
8. The complete request and result are stored in SQLite.
9. A Jinja2 result page is rendered immediately.
10. The result can later be reopened from `/history`.

## Authentication

The browser session uses an HTTP-only signed JWT-compatible cookie. The `/token` endpoint also issues the same signed token as a bearer token for API-style callers. Protected API endpoints accept either the browser cookie or `Authorization: Bearer <token>`.

Passwords are stored as PBKDF2-HMAC-SHA256 hashes with per-user salts using Python's standard library.

## AI integration

The Gemini integration is intentionally isolated in one service so the rest of the application does not depend on a Google SDK. Requests use the configured REST endpoint and ask for JSON-only planner output.

When Gemini is unavailable, the local recommender produces deterministic, structured results so the full product flow remains usable without external credentials.

For Jewelry, an uploaded image is sent as inline base64 data when Gemini is enabled. Without Gemini, the image is still stored and associated with the recommendation request.

## Persistence model

`users` stores login identity and password hashes.

`recommendations` stores:

- user ownership
- planner type
- total budget
- original request JSON
- rendered recommendation JSON
- creation timestamp

## Startup and operational endpoints

- `GET /health` — basic health status.
- `GET /startup` — reports readiness/configuration information corresponding to the design document's startup milestone.

The FastAPI lifespan initializes SQLite and creates the upload directory before serving traffic.
